# Freedom Platform: аудит проекта и материал для презентации

Дата аудита: 2026-09-04  
Формат: внутренний продуктовый и презентационный отчет по репозиторию Freedom Platform.  
Основа аудита: `README.md`, `docs/`, маршруты приложения, API-модули `src/features`, Supabase migrations/functions/views.

## 1. Краткий вывод

Freedom Platform - это multi-tenant SaaS/POS-платформа для управления организациями с физическими рабочими зонами, сменами, заказами, складом и финансами. Проект особенно хорошо подходит для игровых клубов, бильярдных, lounge/VIP-комнат, заведений с почасовой тарификацией, столами, товарами, услугами и комбинированными пакетами.

Главная ценность проекта: система объединяет операционную работу сотрудника, контроль администратора организации и контроль владельца платформы в одном продукте. Это не просто касса и не просто CRM. Freedom Platform закрывает полный цикл: организация -> сотрудники -> рабочие места -> смены -> заказы -> таймеры -> склад -> оплаты -> финансовые периоды -> доля/ежемесячная оплата платформе -> аудит.

Для презентации другим организациям проект можно позиционировать как специализированную управленческую платформу для заведений, где важно одновременно контролировать время, места, продажи, склад, смены, наличность и управленческую отчетность.

## 2. Какую проблему решает проект

Типичная организация в этой сфере часто работает через набор разрозненных инструментов:

- касса или терминал отдельно;
- Excel/Google Sheets для склада и финансов;
- мессенджеры для смен и отчетов;
- ручные заметки по долгам, отказам от оплаты и исправлениям;
- отдельная админка или вообще отсутствие админки;
- отсутствие прозрачного контроля сотрудника в смене;
- отсутствие нормального учета почасовых мест и игровых зон.

Freedom Platform собирает эти процессы в одну систему:

- сотрудник работает в простом рабочем экране;
- администратор видит операционный контроль и управляет каталогом;
- владелец платформы видит все организации, их финансовое состояние и платежи платформе;
- критичные расчеты выполняются на сервере, а не в браузере;
- действия фиксируются в audit log;
- данные организаций разделены через tenant-модель и RLS.

## 3. Целевая аудитория

Основной рынок:

- PlayStation / gaming clubs;
- бильярдные клубы;
- развлекательные lounge-заведения;
- VIP/private room заведения;
- антикафе и пространства с почасовой оплатой;
- заведения, где есть столы, зоны, товары, услуги и смены сотрудников.

Дополнительные возможные рынки:

- компьютерные клубы;
- караоке-комнаты;

- спортивные или leisure-пространства с бронированием зон;

## 4. Позиционирование

Короткая формулировка:

> Freedom Platform - это операционная платформа для заведений с почасовыми зонами, заказами, складом, сменами и финансовым контролем.

Более продающая формулировка:

> Freedom Platform помогает владельцу быстро запускать и контролировать новые организации: настроить структуру заведения, сотрудников, рабочие места, товары, услуги, комбо, смены, заказы, оплаты, склад, финансы и платежи платформе в одной системе.

Для внешней организации:

> Вы получаете готовую цифровую систему управления заведением: сотрудник работает через понятный экран смены, администратор контролирует продажи, склад и финансы, а владелец получает прозрачную отчетность по выручке, расходам, прибыли и задолженности.

## 5. Роли и уровни доступа

- контролирует финансы организаций;
- видит задолженность и платежи платформе;

- может иметь support-доступ к организациям;

## 6. Функциональный аудит

### 6.1. Multi-tenant foundation

Проект построен как multi-tenant система:

- каждая организация является отдельным tenant;
- у организации есть `name`, `slug`, `status`, `timezone`, `currency_code`, `logo_path`, описание;
- маршруты организации используют slug;
- один пользователь может иметь доступ к нескольким организациям;
- глобальная роль `platform_owner` отделена от ролей организации;
- роли организации: `organization_admin`, `employee`;
- статусы организаций позволяют активировать, приостанавливать и архивировать доступ.

Сильная сторона:

- можно создавать новые организации без изменения кода;
- модель подходит для масштабирования на сеть клиентов;
- организация получает свой рабочий контур, но владелец платформы сохраняет общий контроль.

### 6.2. Организации и onboarding

Платформа поддерживает сценарий подключения новой организации:

- создание организации владельцем платформы;
- настройка slug, языка, валюты и timezone;
- назначение администратора;
- проверка readiness организации;
- настройка сотрудников;
- настройка мест, товаров, услуг, комбо, смен и финансов;
- smoke-test перед рабочим запуском.

Это важно для продаж: новым организациям можно предлагать не "пустую программу", а понятный процесс внедрения.

### 6.3. Сотрудники

В проекте нет отдельной дублирующей таблицы employees. Используется связка:

`auth.users -> profiles -> organization_memberships`

Это снижает риск расхождения данных по email, имени, аватару, языку и доступу.

Функции:

- добавление существующего Auth-пользователя как сотрудника;
- поиск пользователя по точному email;
- должность, телефон, заметки, сортировка;
- активация/деактивация сотрудника;
- запрет физического удаления доступа;
- отдельные права для employee и organization admin;
- PIN рабочего места и запрос смены PIN.

Ограничение текущей версии:

- создание Auth-пользователей пока выполняется вручную через Supabase Dashboard;
- полноценный invite-flow через Edge Function отмечен как следующий этап.

### 6.4. Каталог организации

Каталог покрывает структуру заведения:

- категории;
- места;
- товары;
- услуги;
- изображения;
- архивирование/восстановление.

Места:

- обычные столы;
- PlayStation / gaming zones;
- billiard;
- VIP/private rooms;
- racing rigs;
- custom `other` типы;
- места с таймером и без таймера;
- hourly rate, minimum minutes, billing step minutes;
- workspace layout поля для схемы рабочего места.

Товары:

- цена продажи;
- закупочная цена;
- остаток;
- минимальный остаток;
- stock tracking;
- изображения.

Услуги:

- fixed-price;
- hourly;
- без складского учета.

Сильная сторона:

- структура бизнеса настраивается из админки, без доработки кода под каждую организацию.

### 6.5. Изображения и бренд организации

Проект поддерживает загрузку:

- логотипа организации;
- фото категорий;
- фото мест;
- фото товаров;
- фото услуг.

Изображения сжимаются в браузере:

- лимит исходника 5 MB;
- максимальная сторона 1200 px;
- формат WebP;
- качество около 0.8;
- в базе хранится путь, а не base64.

Это полезно для презентации: система может выглядеть как рабочая среда конкретной организации, а не как универсальная безликая касса.

### 6.6. Рабочее место сотрудника

Employee workspace - один из главных продуктовых экранов.

Возможности:

- отображение мест по рабочей схеме;
- статусы мест: свободно, занято, ожидает оплату, недоступно;
- быстрый переход к заказу;
- запуск timed session;
- завершение timed session;
- текущий таймер;
- расчет текущей суммы сессии;
- предупреждения по лимиту времени;
- добавление товаров, услуг, комбо;
- показ остатков для сотрудника в безопасном виде;
- обработка VIP equipment;
- оплата наличными или картой/переводом;
- чаевые;
- разделенная оплата;
- отказ от оплаты с комментарием;
- завершение пустого заказа;
- отмена заказа;
- запросы на исправление заказа.

Сильная сторона:

- сотруднику не нужно видеть управленческие данные, закупочные цены и внутренние финансовые детали;
- интерфейс сфокусирован на скорости работы в смене.

### 6.7. Заказы

Заказы являются центральным бизнес-объектом.

Статусы:

- `open`;
- `waiting_payment`;
- `paid`;
- `unpaid`;
- `payment_refused`;
- `cancelled`.

Заказ может быть:

- без места;
- привязан к столу/месту;
- создан автоматически при запуске timed session.

Важные правила:

- frontend не отправляет итоговые суммы как источник истины;
- сервер snapshot-ит цены каталога;
- сервер пересчитывает totals;
- исторические заказы не ломаются при изменении цен в каталоге;
- stock reservations создаются до оплаты;
- списание склада происходит при оплате или отказе от оплаты, если товар был выдан.

Сильная сторона:

- меньше риск ручных ошибок и манипуляций на клиенте;
- история продаж остается корректной.

### 6.8. Timed sessions и почасовая тарификация

Для заведений с PlayStation, billiard, VIP-room и подобными зонами это ключевая функция.

Система хранит:

- `started_at`;
- `ended_at`;
- `actual_minutes`;
- `billable_minutes`;
- `calculated_amount`;
- тариф;
- minimum minutes;
- billing step.

Текущая бизнес-логика:

- есть grace period 10 минут;
- если фактическое время попадает в минимум + grace, клиент платит минимум;
- после grace система округляет вверх по billing step;
- для The Liga поддержана логика: минимум 60 минут, grace 10 минут, далее округление по 30 минутам.

Дополнительно в рабочей ветке есть развитие логики по included minutes для комбо-пакетов.

### 6.9. Склад

Склад реализован не как простое поле "остаток", а через ledger:

- `stock_documents`;
- `stock_document_items`;
- `stock_movements`;
- cached остаток в products пересчитывается из движений.

Типы складских документов:

- opening balance;
- purchase;
- write off;
- adjustment in;
- adjustment out.

Правила:

- документ сначала создается как draft;
- после posting создаются immutable stock movements;
- отмена не удаляет движения, а создает обратные движения;
- прямое изменение stock_quantity ограничено;
- продажи создают sale movements;
- закупки могут автоматически попадать в финансы.

Сильная сторона:

- можно восстановить историю остатков;
- меньше риск "тихого" изменения склада;
- администратор видит движение товара, а не только текущий остаток.

### 6.10. Комбо

Комбо - это продаваемые пакеты из товаров и услуг.

Поддерживается:

- карточка комбо;
- компоненты комбо;
- fixed selection mode;
- snapshot состава при продаже;
- расчет доступности комбо по складским компонентам;
- safe employee view;
- скрытие закупочной себестоимости от сотрудника;
- возможность включать сервисные минуты в пакетную логику.

Пример ценности:

- организация может продавать пакет "1 час PlayStation + напитки";
- система сохранит состав на момент продажи;
- склад зарезервирует товары;
- время сессии может учитывать включенные минуты.

### 6.11. Смены и касса

Смены закрывают ответственность сотрудника.

Функции:

- шаблоны смен;
- смены через полночь;
- business date с учетом timezone организации;
- до 06:00 раннее утро относится к предыдущему business date;
- открытие смены сотрудником;
- запрет дублирования открытой смены;
- блокировка workspace без открытой смены;
- серверная привязка действий к shift context;
- закрытие смены;
- расчет cash sales;
- расчет card/transfer sales;
- expected cash;
- actual cash;
- variance;
- комментарий при расхождении;
- handover открытых заказов/сессий следующему сотруднику.

Сильная сторона:

- владелец видит, кто работал, когда, какие заказы были в смене, сколько наличных должно быть и где расхождение.

### 6.12. Операционные дни

Операционный день агрегирует смены по business date:

- total revenue;
- cash revenue;
- card transfer revenue;
- unpaid total;
- payment refused total;
- счетчики заказов;
- завершение дня, когда нет открытых смен.

Это полезно для ежедневного контроля заведения и для сообщений руководителю.

### 6.13. Оплаты

Поддерживаемые методы:

- cash;
- card/transfer.

Функции:

- полная оплата заказа;
- оплата с чаевыми;
- split payment;
- отказ от оплаты с обязательным комментарием;
- автоматическое списание выданных товаров даже при отказе от оплаты;
- создание финансового income при успешной оплате;
- привязка оплаты к смене.

Сильная сторона:

- система разделяет кассовый факт, финансовый факт и складской факт;
- отказ от оплаты не превращается в скрытую потерю склада.

### 6.14. Исправления и контроль ошибок

Сотрудник не удаляет позиции напрямую.

Он создает `order_adjustment_requests`:

- удалить позицию;
- изменить количество;
- отменить заказ;
- изменить метод оплаты;
- исправить время сессии;
- другое.

Администратор проверяет и утверждает/отклоняет запрос.

Сильная сторона:

- ошибки исправляются контролируемо;
- сохраняется история;
- снижается риск злоупотреблений со стороны сотрудника.

### 6.15. Финансы организации

Финансовый модуль добавлен поверх заказов, смен и склада.

Функции:

- finance categories;
- income;
- expenses;
- purchases;
- recurring expenses;
- expense approval;
- finance dashboard summary;
- P&L;
- cash flow;
- financial periods;
- отправка периода на проверку;
- проверка периода platform owner;
- locking финансового периода;
- finance audit log.

Автоматизация:

- оплаченный заказ создает income;
- повторный income по одному заказу запрещен индексом;
- payment_refused не попадает в доходы;
- COGS считается по snapshot-себестоимости order items;
- purchase stock document создает purchase transaction;
- закупка влияет на cash flow, но не включается в P&L как COGS.

Сильная сторона:

- организация получает не только продажи, но и управленческую финансовую картину.

### 6.16. Финансы платформы

Для владельца Freedom Platform есть отдельный контур:

- общий обзор организаций;
- доходы и расходы организаций;
- чистая прибыль организаций;
- периоды на проверке;
- задолженность по оплате платформе;
- платежи, ожидающие подтверждения;
- детализация финансов организации;
- подтверждение оплат платформе.

Модель монетизации поддерживает:

- процентную долю платформы;
- ежемесячную фиксированную оплату платформе.

Это критично для бизнес-модели: владелец может подключать новые организации и контролировать их обязательства перед платформой.

### 6.17. Telegram уведомления

Проект содержит notification outbox:

- настройки уведомлений по организации;
- Telegram chat id;
- Edge Function `process-notification-outbox`;
- claim pending rows через atomic workflow;
- retry/backoff;
- дедупликация;
- статусы sent/cancelled/failed.

Сценарии:

- уведомление об открытии смены;
- daily summary;
- операционные уведомления руководителю.

Сильная сторона:

- уведомления отделены от бизнес-операций;
- если Telegram временно недоступен, основная операция не должна ломаться.

### 6.18. Audit log

Система фиксирует значимые события:

- создание заказа;
- добавление позиции;
- запрос исправления;
- approve/reject исправления;
- старт сессии;
- завершение сессии;
- оплата;
- отказ от оплаты;
- перенос заказа;
- действия по финансам;
- просмотры/активность admin-разделов.

Сильная сторона:

- владелец и администратор могут разбирать спорные ситуации по фактам, а не по словам.

### 6.19. Безопасность данных

В проекте заложены сильные технические решения:

- Supabase Auth;
- RLS;
- разделение global platform roles и organization memberships;
- safe employee views;
- запрет доступа сотрудников к закупочным ценам и себестоимости;
- RPC для критичных операций;
- direct write guards на критичных таблицах;
- `service_role` только для серверных сценариев/Edge Functions;
- Storage policies для organization assets;
- idempotency для важных финансовых операций;
- locked-period guards;
- atomic notification claiming.

Сильная сторона:

- это не просто frontend-приложение поверх открытых таблиц; критичная логика вынесена на уровень базы и RPC.

### 6.20. PWA, языки и UX

Проект имеет:

- PWA manifest;

- responsive интерфейс;
- русскую и азербайджанскую локализацию;
- иконки и плотную операционную навигацию;

Это важно для заведений, где сотрудники могут работать с планшета, ноутбука или мобильного устройства.

## 7. Чем Freedom Platform отличается от обычных управленческих программ

### 7.1. Не универсальная CRM, а операционная система заведения

Многие CRM хранят клиентов, задачи и сделки. Freedom Platform сфокусирована на реальной работе заведения:

- места;
- таймеры;
- заказы;
- смены;
- касса;
- склад;
- комбо;
- операционные дни.

### 7.2. Почасовые зоны встроены в ядро

Для gaming/billiard/lounge бизнеса почасовая тарификация часто является основной выручкой. В Freedom Platform это не workaround, а отдельная модель timed sessions с server-side расчетом.

### 7.3. Склад связан с продажами

Продажа товара создает reservation и затем stock movement. Это сильнее, чем простое списание числа из поля.

### 7.4. Финансы связаны с операциями

Оплаченные заказы автоматически попадают в доходы, закупки попадают в cash flow, COGS считается по snapshots. Это снижает ручной учет.

### 7.5. Есть отдельный контур владельца платформы

Большинство программ решают задачу одной организации. Freedom Platform уже имеет уровень platform owner, который может подключать и контролировать много организаций.

### 7.6. Employee-доступ ограничен

Сотрудник видит то, что нужно для работы, но не видит закупочную цену, себестоимость, внутренние финансовые таблицы и audit logs.

### 7.7. Исправления проходят через approve workflow

Это отличает систему от простых POS-экранов, где сотрудник может напрямую удалить позицию или изменить заказ.

### 7.8. Есть контроль смены и кассовой ответственности

Система считает expected cash, actual cash, variance и требует комментарий при расхождении.

### 7.9. Подготовлена основа для масштабирования

Multi-tenant модель, organization slug routes, platform finance, RLS и onboarding checklist позволяют подключать новые организации по повторяемому процессу.

## 12. SWOT-аудит

### Strengths

- Платформа уже имеет multi-tenant архитектуру.
- Есть разные роли и отдельные пользовательские контуры.
- Операционная логика покрывает реальные процессы заведения.
- Почасовая тарификация встроена в продукт.
- Склад работает через ledger, а не через ручное поле.
- Финансы связаны с заказами и складом.
- Есть audit log и approve workflow.
- Есть PWA-основа и RU/AZ локализация.
- Есть платформа для подключения новых организаций.

### Weaknesses

- Invite-flow пользователей пока не завершен.
- Backup/export описан как план, но не реализован как готовый модуль.
- Нужны реальные production smoke-tests на Supabase окружении.
- Нужна проверка всех миграций и RLS на живой базе.
- Нужна аккуратная подготовка демо-данных для продаж.
- Нет внешнего рыночного сравнения с конкретными конкурентами в репозитории.

### Opportunities

- Продавать как SaaS для gaming/billiard/lounge рынка.
- Делать быстрые пилоты для конкретных заведений.
- Добавить платные тарифы по организациям.
- Добавить invite-flow и self-service onboarding.
- Добавить booking/reservation.
- Добавить зарплаты/мотивацию сотрудников.
- Добавить export и backup center.
- Добавить Telegram/WhatsApp отчеты владельцу.
- Добавить BI-дашборды по сети организаций.

### Threats

- Ошибки в финансовой логике могут сильно влиять на доверие.
- Слабая миграционная дисциплина может усложнить production запуск.
- Без хорошего onboarding новые организации могут не понять ценность.
- Если интерфейс сотрудника будет медленным, система не приживется в смене.
- Конкуренты с готовыми POS/ERP могут выигрывать по зрелости фискальных интеграций.

Freedom Platform - это система управления заведением, где есть рабочие места, почасовая тарификация, товары, услуги, смены и финансы. Она помогает сотруднику быстро обслуживать клиентов, администратору контролировать операции, а владельцу видеть реальную картину бизнеса.

## 19. Итоговая оценка

Freedom Platform уже выглядит не как простой MVP, а как специализированная операционная платформа с серьезной архитектурной основой. Самая сильная сторона - связка операционного учета, смен, склада, финансов и platform-owner контроля.
