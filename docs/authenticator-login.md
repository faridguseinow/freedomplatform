# Вход через аутентификатор (TOTP)

Второй шаг входа для администраторов и сотрудников организации: после пароля пользователь вводит 6-значный код из приложения-аутентификатора (Google Authenticator, Microsoft Authenticator, 1Password, Authy и любое другое TOTP-приложение). Используется встроенный Supabase Auth MFA.

Настройка включается отдельно для каждой организации. Сейчас она предназначена для The Liga; новые организации подключаются по желанию.

## Как это работает для пользователя

1. Первый вход после включения: пароль, затем экран «Подключите аутентификатор» с QR-кодом. Пользователь сканирует его в приложении и вводит код. С телефона можно нажать «Открыть в приложении-аутентификаторе» или ввести ключ вручную.
2. Следующие входы: пароль, затем экран «Код из аутентификатора».
3. Сессия после проверки кода живёт как обычно (обновление токена сохраняет второй шаг), поэтому на рабочем устройстве код не нужно вводить постоянно, только при новом входе.
4. Потерян телефон: администратор организации открывает сотрудника в разделе «Сотрудники» и нажимает «Сбросить аутентификатор». Владелец платформы может сбросить аутентификатор любому пользователю, включая администратора, в разделе «Пользователи организации». После сброса пользователь подключает новый аутентификатор при следующем входе.

## Как это защищено

- Колонка `organizations.mfa_required` (по умолчанию `false`).
- Проверка выполняется в базе данных, а не только в интерфейсе. Функции доступа `is_organization_member`, `is_organization_admin`, `current_user_organization_ids`, `current_user_role`, `current_user_primary_organization_id`, на которых построены RLS-политики и RPC, не признают членство в такой организации, пока в JWT сессии нет `aal = aal2`. Украденный пароль без кода не даёт доступа к данным, даже через прямые запросы к API.
- `get_my_mfa_requirement()` сообщает приложению только одно: нужен ли второй шаг текущему пользователю. Это безопасно вызывать до проверки кода.
- Изменить `mfa_required` из приложения может только владелец платформы (триггер `organizations_mfa_requirement_guard`). Администратор организации не может отключить защиту.
- Edge Function `reset-user-mfa` удаляет TOTP-факторы через service role на сервере. Ключ service role во frontend не попадает. Администратор организации может сбрасывать только сотрудников своей организации и только если сам вошёл с кодом.
- На владельца платформы требование не распространяется.

## Включение и выключение

- Владелец платформы: «Организации» → «Пользователи» нужной организации → карточка «Вход через аутентификатор» → «Включить» / «Выключить».
- Через SQL (например, в Supabase SQL editor):

```sql
update public.organizations set mfa_required = true where slug = 'theliga';
-- откат
update public.organizations set mfa_required = false where slug = 'theliga';
```

## Порядок развёртывания

1. В Supabase Dashboard → Authentication → Multi-Factor проверить, что «App Authenticator (TOTP)» включён (на облачных проектах он включён по умолчанию).
2. Применить миграцию `202611271001_organization_mfa_requirement.sql`. Она ничего не меняет для пользователей, пока флаг выключен.
3. Задеплоить Edge Function `reset-user-mfa` (`supabase functions deploy reset-user-mfa`).
4. Задеплоить frontend.
5. Применить `202611271002_enable_mfa_for_the_liga.sql` (или включить кнопкой). С этого момента все пользователи The Liga при следующем входе подключают аутентификатор, а уже открытые сессии сразу попросят код.

Важно: не включать флаг до деплоя frontend, иначе старая версия приложения покажет пользователям The Liga сообщение о недоступной организации вместо экрана ввода кода.

## Проверка после включения

1. Войти сотрудником The Liga: должен появиться QR-код. Подключить, ввести код, попасть в рабочее место.
2. Выйти и войти снова: должен появиться только запрос кода. Неверный код показывает ошибку.
3. Войти администратором The Liga: тот же сценарий, затем «Сотрудники» → сотрудник → «Сбросить аутентификатор». Следующий вход сотрудника снова показывает QR-код.
4. Войти пользователем другой организации: второй шаг не запрашивается.
