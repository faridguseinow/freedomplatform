# Локализация Freedom Platform

Интерфейс использует `i18next` и поддерживает `az`, `ru` и `en`.

Английский каталог пока полностью покрывает демо-вход. На остальных экранах отсутствующие
английские строки берутся из русского fallback-каталога.

## Где исправлять перевод

- Основной русский каталог: `locales/ru.json`
- Основной азербайджанский каталог: `locales/az.json`
- Английский каталог демо: `locales/en.json`
- Новые и динамические сообщения: `locales/manual.ru.json` и `locales/manual.az.json`

Значения можно редактировать вручную. Ключи менять нельзя: они используются в коде.

## Как добавить новое сообщение

1. Добавить одинаковый смысловой ключ в оба файла `manual.*.json`.
2. Использовать ключ через `const { t } = useI18n()`:

```tsx
t('orders.created')
t('orders.total', { amount })
```

3. Запустить `npm run i18n:check`.

Сборка автоматически запускает эту проверку и завершится ошибкой, если ключ отсутствует в одном из языков, перевод пустой или в код добавлен динамический русский шаблон без i18n-интерполяции.

## Ошибки сервера

Тексты ошибок из базы (`raise exception '...'` в `supabase/migrations`) переводятся на клиенте:

- соответствие «английский текст → ключ» лежит в `src/lib/errors/serverErrorCatalog.ts`;
- переводы — ключи `serverError.*` в `manual.ru.json`, `manual.az.json` и `en.json`;
- в API-слое ошибки Supabase выбрасываются через `toServerError(error)`, поэтому `error.message` уже переведён;
- для проверок по исходному тексту (`includes('...')`) используйте `getRawErrorMessage(error)`.

Если в миграции появилась новая ошибка, добавьте её в каталог и переводы. Без этого она покажется пользователю как есть, на английском.
